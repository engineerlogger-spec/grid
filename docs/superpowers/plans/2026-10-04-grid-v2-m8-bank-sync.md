# Grid v2: M8 (Bank sync) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Executed inline on branch `bank-sync`. Pure units are test-first (TDD). Following the project convention (see the M4 plan), each task gives exact files, signatures, rules and test cases; the code is written during execution.

**Goal:** Sync booked Revolut transactions through Enable Banking and reconcile them with the ledger, so that Revolut, Google Wallet and PayPal spending lands in Grid automatically (spec: `docs/superpowers/specs/2026-10-04-bank-sync-design.md`).

**Architecture:**
- **Pure Kotlin** in `core/bank`: `DescriptorCleaner`, `TxClassifier`, `MccCategories`, `MatchRules`, `ExternalIds`.
- **HTTP:** `EnableBankingClient` signs every request with an RS256 JWT.
- **Room:** `BankRepository` and `BankReconciler`.
- **Orchestration:** `BankSync` runs from `BankSyncWorker` and from the UI.
- **UI:**
  - `feature/bank/BankSetupScreen`
  - a Bank section in `DetectedScreen`
  - a Home reconnect card

**Tech stack:**
- Existing: OkHttp 5, kotlinx-serialization, Room 2.8 (AutoMigration 1→2), WorkManager, Hilt, Compose.
- `java.security` for RSA and the AndroidKeyStore. No new dependencies.

**Rules for every task:**
- `.\scripts\unit.ps1` must stay green.
- Commit after each task, with a message ending in the Co-Authored-By line.
- Never run Gradle while the emulator E2E runs.

## Task 2: DescriptorCleaner (pure, TDD)

**Files**
- Create: `core/bank/DescriptorCleaner.kt`
- Test: `core/bank/DescriptorCleanerTest.kt`

**API:** `object DescriptorCleaner { data class Cleaned(val merchant: String, val via: PaymentKind?); fun clean(raw: String): Cleaned? }` returns null for a blank input.

**Rules, in order:**
1. Trim and collapse whitespace.
2. `(?i)^(paypal|pp)\s*\*\s*(.+)$` gives merchant = group 2 and `via = PAYPAL`.
3. `(?i)^paypal\b.*` with nothing after `*` gives `Cleaned("PayPal", PAYPAL)`.
4. Strip processor prefixes `(?i)^(sq|sumup|iz|zettle|sp|ubr)\s*\*\s*` and `(?i)^zettle_`.
5. Strip a trailing store number: `\s+#?\d{3,}$`.
6. Strip a trailing country code when other text remains: ` (FR|FRA|GB|GBR|DE|DEU|ES|ESP|IT|ITA|NL|NLD|BE|BEL|LT|LTU|IE|IRL|PT|PRT|LU|LUX|US|USA)$`.
7. If the result has no lowercase letters, title-case each word (`STARBUCKS COFFEE` becomes `Starbucks Coffee`). Mixed case is kept as is.

**`TxClassifier.classify(tx: RemoteTx, ownIbans: Set<String>): BankTxKind`:**
- Direction: `creditDebit == "CRDT"` means IN; anything else means OUT.
- `text` = the counterparty name and remittance lines, joined and lowercased.
- **INTERNAL** when:
  - the counterparty IBAN (creditor for OUT, debtor for IN) is in `ownIbans`, compared without spaces and case-insensitively; or
  - `text` matches `\b(to|from) (\w+ )?(vault|pocket|savings)\b`, `\bexchanged? (to|from)\b`, `\btop[- ]?up\b`, `\bflexible (cash )?funds?\b`, `\b(stocks?|crypto|commodities)\b` or `\binvestment account\b`.
- **MONEY_IN:** any other IN.
- **DIRECT_DEBIT** (OUT):
  - `bankTxCode` contains `DD`, `PMDD` or `direct debit` (case-insensitive); or
  - `text` matches `\b(direct debit|sepa dd|pr[ée]l[èe]vement|mandate)\b`.
- **TRANSFER_OUT** (OUT):
  - `creditorIban != null`; or
  - `bankTxCode` contains `TRF`, `ICDT` or `transfer`; or
  - the first remittance line matches `(?i)^to [\p{L} .'-]+$`.
- **CARD_SPEND** otherwise.

## Task 4: MatchRules (pure, TDD)

**Files**
- Create: `core/bank/MatchRules.kt`
- Test: `MatchRulesTest.kt`

**API:**
```kotlin
data class BankFacts(val type: TxType, val kind: BankTxKind, val amountMinor: Long, val occurredAt: Long, val merchant: String?)
data class Candidate(val id: Long, val source: TxSource, val amountMinor: Long, val occurredAt: Long, val merchant: String?)
object MatchRules {
    fun similar(a: String?, b: String?): Boolean
    fun bestMatch(bank: BankFacts, candidates: List<Candidate>): Candidate?
}
```

**`similar`** is true when either side is null or blank, or when the `MerchantKey.of` token sets share a token of at least 3 characters.

**Eligibility per candidate source** (`d` = days from the bank date to the candidate date, candidate minus bank):

| Source | Date window | Amount | Name |
|---|---|---|---|
| CAPTURE, MANUAL | −5 ≤ d ≤ 1 | exact, or within 5% | `similar` required |
| SUBSCRIPTION, PENDING | \|d\| ≤ 3 | within 10% with `similar`, or within 2% without it | see amount |
| CHECKIN (only when `bank.type == INCOME`) | \|d\| ≤ 7 | within 10% | not required |
| BANK | never | | |

**Best match:** the smallest relative amount difference, then the smallest |d|, then the lowest id.

**Tests:**
- A capture of €4.50 Starbucks on the same day matches.
- A capture with a different merchant (`Lidl` vs `Starbucks`) does not match.
- With two €3.50 `Coffee` captures and one bank €3.50 Coffee, the nearer one is picked.
- A subscription `Netflix` €13.49 matches bank €13.99 Netflix (within 10%, similar).
- A subscription `Rent` €850 matches bank €850 `J. Dupont` (within 2%, name not needed).
- A subscription `Rent` €850 does not match €900 `J. Dupont`.
- A capture dated 6 days before the bank date does not match.
- CHECKIN salary €2,500 matches a bank income of €2,463 four days later.
- A BANK-source candidate never matches.

## Task 5: Key handling, JWT, key store (TDD)

**Files**
- Create: `core/bank/BankCrypto.kt`, `core/bank/BankKeyStore.kt`
- Test: `BankCryptoTest.kt`, `BankKeyStoreTest.kt`

**`BankCrypto`:**
- `object PemKeys { fun parsePrivateKey(pem: String): PrivateKey }`:
  - Accepts `BEGIN PRIVATE KEY` (PKCS#8).
  - Accepts `BEGIN RSA PRIVATE KEY` (PKCS#1), wrapped into PKCS#8 by prefixing the DER `SEQUENCE{INTEGER 0, AlgorithmIdentifier rsaEncryption NULL, OCTET STRING <pkcs1>}`.
  - Throws `IllegalArgumentException("Not an RSA private key")` for anything else.
- `object EnableBankingJwt { fun sign(appId: String, key: PrivateKey, nowSeconds: Long, ttlSeconds: Long = 3600): String }`:
  - The header JSON is `{"typ":"JWT","alg":"RS256","kid":appId}`.
  - The claims are `{"iss":"enablebanking.com","aud":"api.enablebanking.com","iat":now,"exp":now+ttl}`.
  - It is base64url without padding, signed with `SHA256withRSA`.
- **Tests:**
  1. Generate an RSA-2048 key pair in the test.
  2. Export it as a PKCS#8 PEM and parse it back.
  3. Sign, then verify the signature with the public key.
  4. Check that the header and claims decode to the expected values.
  5. Check that the PKCS#1 PEM of the same key parses to an equal key. Build it from the PKCS#8 encoding by stripping the 26-byte header.
  6. Check that garbage input throws.

**`BankKeyStore`:**
- `interface SecretBox { fun seal(plain: ByteArray): ByteArray; fun open(sealed: ByteArray): ByteArray }`.
- `class KeystoreSecretBox : SecretBox`:
  - Uses an AndroidKeyStore AES-256-GCM key, alias `grid.bank`.
  - The output is `iv(12) + ciphertext`.
- `data class BankCredentials(val appId: String, val privateKeyPem: String)`.
- `class BankKeyStore(private val file: File, private val box: SecretBox)`:
  - `save(c)` writes the sealed JSON of `c`.
  - `load(): BankCredentials?` returns null when the file is missing or can't be opened.
  - `clear()`.
  - `hasCredentials()`.
- The file lives at `context.noBackupFilesDir/bank.key`, which is never copied by Android backup.
- **Tests** (with a fake XOR box):
  - save then load round-trips.
  - a corrupt file loads as null.
  - clear removes the file.
- **DI** in `AppModules`:
  - `@Provides @Singleton fun bankKeyStore(ctx)` returns `BankKeyStore(File(ctx.noBackupFilesDir, "bank.key"), KeystoreSecretBox())`.

## Task 7: BankRepository (Robolectric)

**Files**
- Create: `core/data/repo/BankRepository.kt`
- Test: `core/data/repo/BankRepositoryTest.kt`

**API:**
- **Connection lifecycle:**
  - `observeConnection(): Flow<BankConnectionEntity?>` and `connection()`.
  - `beginAuth(aspsp: Aspsp, state: String, backfillFromEpochDay: Long?)` creates or updates the single connection with status `NEEDS_SETUP` and `authState = state`.
  - `completeAuth(state: String, session: BankSession): List<BankAccountEntity>`:
    - Requires `state == authState`; otherwise it throws `IllegalStateException`.
    - Sets `sessionId`, `validUntil`, `status = ACTIVE`, `authState = null`.
    - Upserts accounts by `identificationHash`. A new account is enabled when its currency matches the app currency (the caller passes `appCurrency`). Existing accounts keep their `enabled` flag and `syncedThroughEpochDay` and update their `uid`.
  - `setEnabled(accountId, enabled)`.
  - `markStatus(status, error: String?)`.
  - `recordSync(at)`.
  - `disconnect()` deletes the connection; accounts and staged rows cascade, and ledger rows stay.
- **Review groups:** `observeReviewGroups(): Flow<List<BankReviewGroup>>`.
  - The data shape is `data class BankReviewGroup(val key: String, val kind: ReviewKind, val title: String, val count: Int, val totalMinor: Long, val currency: String, val latestAt: Long, val ids: List<Long>)`.
  - `enum class ReviewKind { CATEGORISE, DECIDE_OUT, DECIDE_IN }`.
  - **CATEGORISE** groups are ledger transactions with `needsReview`, grouped by `MerchantKey.of(merchant) ?: "?"`. `title` is the latest merchant, and `ids` are transaction ids.
  - **DECIDE_\*** groups are staged rows in `NEEDS_DECISION`, grouped by `(direction, counterpartyKey ?: "?")`. `ids` are staged ids.
  - Sort by `latestAt` descending.
- **Review actions:**
  - `categorise(group, categoryId)`: for each tx, `TransactionRepository.update` with the new category and `needsReview = false`, which teaches the merchant rule.
  - `book(group, categoryId, appMethodId: Long?)`: for each staged row, add a ledger tx (EXPENSE for OUT, INCOME for IN, `source = BANK`, merchant = counterparty, occurredAt, method = `via` or the Revolut method), link it and set the state to `BOOKED`. Saving a merchant teaches the rule, so later transfers to the same counterparty auto-book.
  - `ignore(group, always: Boolean)`: sets the state to `IGNORED`, and when `always` is true, inserts `BankIgnoreRuleEntity(key)` for DECIDE groups.
  - `recentRaw(limit = 20): String`: a JSON array of raw rows, used for the Share action.
- **`TransactionRepository` changes:**
  - `update` forces `needsReview = false`, because any user edit counts as a review.
  - New `applyBank(id: Long, amountMinor: Long, methodId: Long?)` updates the amount, and the method when the current one is null. It notifies listeners.
- **Tests:**
  - `completeAuth` with a wrong state throws.
  - A reconnect keeps the enabled flags and swaps the uids.
  - Grouping counts and totals are correct.
  - `categorise` clears `needsReview` and creates a rule.
  - `book` creates linked transactions with the right type.
  - `ignore(always = true)` stores the rule.

## Task 8: BankReconciler (Robolectric, TDD)

**Files**
- Create: `core/bank/BankReconciler.kt`
- Modify: `core/data/repo/PendingRepository.kt`
- Test: `core/bank/BankReconcilerTest.kt`

**`PendingRepository.settle(id, amountMinor: Long? = null, at: Long? = null): Long?`** returns the transaction id. Existing callers are unchanged.

**`BankReconciler.process(row: BankTransactionEntity, appCurrency: String): BankTxState`** writes the state, the link and any ledger changes in one Room transaction. The order is:
1. `kind == INTERNAL` → `IGNORED`.
2. `currency != appCurrency` → `NEEDS_DECISION`.
3. An ignore rule exists for `counterpartyKey` → `IGNORED`.
4. Ledger match:
   - Load `ledgerCandidates` for `type = (OUT → EXPENSE, IN → INCOME)` within [occurredAt − 7d, occurredAt + 7d].
   - Map them to `Candidate` and run `MatchRules.bestMatch`.
   - On a hit:
     - Call `transactions.applyBank(hit.id, row.amountMinor, methodFor(row.via))`.
     - Link the row and return `BOOKED`.
5. Bill match:
   - **OUT:** check active subscriptions with an amount within 2% (or within 10% with `MatchRules.similar(sub.name, merchant)`) that have a charge date within ±3 days. That is true exactly when `BillingSchedule.nextOnOrAfter(anchor, cycle, D-3) <= D+3`.
     - On a hit, insert `source = BANK`, `subscriptionId`, `categoryId = sub.categoryId`, link it and return `BOOKED`.
   - Then check open pending payments (`PENDING`, direction matching: OUT ↔ I_OWE, IN ↔ OWED_TO_ME, same currency) with the same amount tolerance against `title` or `counterparty`, and a due date within ±3 days or no due date.
     - On a hit, call `pending.settle(id, row.amountMinor, row.occurredAt)`, link the transaction and return `BOOKED`.
6. **CARD_SPEND or DIRECT_DEBIT:** create a `BANK` transaction.
   - Category: the rule for `MerchantKey(merchant)`, else `MccCategories` (via `categoryDao.byIconKey`), else `Other` with `needsReview = true`.
   - Method: the rule's method, else `via`, else the Revolut method.
   - Link it and return `BOOKED`.
7. **TRANSFER_OUT or MONEY_IN:** if a rule exists whose category kind matches the direction, create the transaction (as in step 6, with no needsReview) and return `BOOKED`. Otherwise return `NEEDS_DECISION`.

## Task 9: BankSync, ExternalIds, DemoBank, connector factory

**Files**

**`ExternalIds.assign(page: List<RemoteTx>): List<Pair<String, RemoteTx>>`:**
- The id is `transactionId`, else `entryReference`, else `"h:" + sha1(bookingDate|amount|creditDebit|counterparty|remittance.joinToString)`, plus `"#n"` where n is the 0-based ordinal among identical hashes in the page.
- Tests: ids are preferred over hashes, and two identical coffees get `#0` and `#1`.

**`BankSync.run(userInitiated: Boolean): SyncResult`:**
- The result type is `sealed interface SyncResult { data class Ok(val fetched: Int, val booked: Int, val toReview: Int); data object NotConnected; data object Expired; data object RateLimited; data class Failed(val message: String) }`.
- Mutual exclusion with a `Mutex`.
- Steps:
  1. With no connection or no session → `NotConnected`.
  2. If `validUntil < now` → mark `EXPIRED` and return `Expired`.
  3. For each enabled account:
     - `from = (syncedThroughEpochDay ?: backfillFromEpochDay ?: today-90) - 5 days`.
     - Page until `continuationKey == null`.
     - Keep `status == null || status == "BOOK"`.
     - Map each item:
       - occurredAt is the noon of `transactionDate ?: bookingDate ?: valueDate` in the clock zone.
       - Amount via `Currencies.toMinor`.
       - Direction from `creditDebit`.
       - Kind via `TxClassifier` with the IBANs of all accounts.
       - Counterparty: creditor for OUT, debtor for IN, else the first remittance line.
       - Clean it with `DescriptorCleaner` to get `via`, then compute `counterpartyKey`.
     - `insertStaged`; collect the rows that were actually new.
  4. Reconcile the new rows in ascending `occurredAt` order.
  5. Update `syncedThroughEpochDay = today`, `recordSync`, and status `ACTIVE`.
- Errors:
  - `SessionExpired` or `Unauthorized` → mark `EXPIRED`, return `Expired`.
  - `RateLimited` → `RateLimited`.
  - `Network` or `Http` → `Failed` with `lastError` saved.

**`BankConnectors.current(): BankConnector`:**
- Returns `DemoBankConnector(clock)` when `BuildConfig.DEBUG && creds.appId == "demo"`.
- Otherwise returns `EnableBankingClient(http, { keyStore.load()!! }, ...)`.

**`DemoBankConnector`** (canned data relative to `clock.today()`):

- `startAuth` returns `url = "grid://bank-callback?code=demo&state=$state"`.
- `createSession` returns one EUR account `uid = "demo-eur"`, iban `LT00DEMO0000000001`.
- `transactions` returns, for the last 3 months:

  - Internal: `To EUR Vault` €200.

  - All with `status = "BOOK"`.
